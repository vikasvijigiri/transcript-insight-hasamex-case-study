# Phase 2: Frontend Redesign — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the frontend as the researched 3-pane "grounded research intelligence" design — left rail nav, center content, source panel that scrolls-to and highlights the exact cited passage — on top of shadcn/ui (Radix), replacing the current plain top-tab layout.

**Architecture:** shadcn/ui components (Radix primitives) as the foundation, SWR for data fetching (replacing hand-rolled `useEffect`+`fetch`), a new feature-based folder structure, and a client-side highlight mechanism keyed off `citation.start_char` (from Phase 1). No backend changes in this phase — Phase 1 must be complete and merged first, since the source panel depends on `GET /api/experts/{id}/transcript` and `Citation.start_char` existing.

**Tech Stack:** Next.js 16 (App Router), React 19, Tailwind v4, shadcn/ui (Radix), SWR, next-themes.

**Spec:** `docs/superpowers/specs/2026-09-22-frontend-redesign-design.md` §3-§6, §8-§10. Full reasoning in `design/FRONTEND_BEST_PRACTICES_CHECKLIST.md`.

## Global Constraints

- shadcn init uses Radix, not the new Base UI default: `npx shadcn@latest init -b radix` (spec §3 — stability over "current default" given the deadline).
- No `dangerouslySetInnerHTML` anywhere (spec §5) — the highlight split in Task 6 is built as real React elements.
- Every transition uses `transform`/`opacity` only, never `width`/`height`/`top`/`margin`, and respects `prefers-reduced-motion` (spec §6).
- Touch targets ≥44×44px, contrast ≥4.5:1 normal text / ≥3:1 large text, focus rings ≥3:1 contrast (spec §6, WCAG 2.2 AA).
- Skeleton loading states must match real content dimensions (no CLS regression).
- Every task ends with `npm test -- --run`, `npx tsc --noEmit`, and `npm run lint` all clean before moving on. `npm run build` gets a final check at the end of the phase, not after every task (it's slower and less informative mid-task than the other three).

```tsx
"use client";

import useSWR from "swr";
import { useState } from "react";
import { api, ExpertMeta } from "@/lib/api";
import CitationChips from "@/components/CitationChips";
import { Button } from "@/components/ui/button";
import { Skeleton } from "@/components/ui/skeleton";

export default function ExpertQAPanel({ experts }: { experts: ExpertMeta[] }) {
  const [activeId, setActiveId] = useState(experts[0]?.id ?? "");
  const { data, error, isLoading, mutate } = useSWR(
    activeId ? `expert-qa-${activeId}` : null,
    () => api.expertQA(activeId),
  );

  return (
    <div>
      <div className="mb-4 flex flex-wrap gap-2">
        {experts.map((e) => (
          <button
            key={e.id}
            onClick={() => setActiveId(e.id)}
            className={`min-h-11 rounded-full px-4 py-1.5 text-sm font-medium transition-[background-color,color] duration-150 ${
              activeId === e.id
                ? "bg-zinc-900 text-white dark:bg-zinc-100 dark:text-zinc-900"
                : "bg-zinc-100 text-zinc-700 hover:bg-zinc-200 dark:bg-zinc-800 dark:text-zinc-300"
            }`}
          >
            {e.name} · {e.market}
          </button>
        ))}
      </div>

      {isLoading && (
        <div className="flex flex-col gap-4">
          <Skeleton className="h-4 w-48" />
          <Skeleton className="h-24 w-full" />
        </div>
      )}
      {error && (
        <div className="text-sm text-red-600">
          <p>{String(error.message ?? error)}</p>
          <Button variant="outline" size="sm" className="mt-2" onClick={() => mutate()}>
            Try again
          </Button>
        </div>
      )}

      {data && (
        <div className="flex flex-col gap-4">
          <div className="text-sm text-zinc-500">
            {data.role} — {data.market}
          </div>
          {data.answers.map((a, i) => (
            <div key={i} className="rounded-lg border border-zinc-200 p-4 shadow-sm dark:border-zinc-800">
              <p className="text-sm font-semibold text-zinc-500">
                Q{i + 1}. {a.question}
              </p>
              <p className="mt-2 text-base leading-relaxed text-zinc-900 dark:text-zinc-100">{a.answer}</p>
              <CitationChips citations={a.citations} />
            </div>
          ))}
        </div>
      )}
    </div>
  );
}
```

Note: the derived-loading-state logic from the earlier session (comparing `data.expert_id` to `activeId` to avoid stale-data flashes) is superseded here — SWR keys the cache by `expert-qa-${activeId}`, so switching experts naturally shows the new key's own loading/data state, not the previous key's stale data. This is what the spec (§4) means by SWR making that hand-rolled logic "largely redundant."

- [ ] **Step 3: Implement `TranscriptView`**

Implements spec §8's mechanism exactly: offset-first with a defensive `indexOf` fallback, plain React elements (no `dangerouslySetInnerHTML`), `scrollIntoView` centering.

```tsx
"use client";

import { useEffect, useRef } from "react";
import { TranscriptSegment } from "@/lib/api";

export function TranscriptView({
  rawText,
  segments,
  highlightStartChar,
  highlightQuote,
}: {
  rawText: string;
  segments: TranscriptSegment[];
  highlightStartChar?: number;
  highlightQuote?: string;
}) {
  const markRef = useRef<HTMLElement>(null);

  useEffect(() => {
    markRef.current?.scrollIntoView({ behavior: "smooth", block: "center" });
  }, [highlightStartChar, highlightQuote]);

  if (highlightStartChar === undefined || !highlightQuote) {
    return <TranscriptBody rawText={rawText} segments={segments} />;
  }

  const matchesAtOffset = rawText.slice(highlightStartChar, highlightStartChar + highlightQuote.length) === highlightQuote;
  const start = matchesAtOffset ? highlightStartChar : rawText.indexOf(highlightQuote);

  if (start === -1) {
    return <TranscriptBody rawText={rawText} segments={segments} />;
  }

  const end = start + highlightQuote.length;
  const before = rawText.slice(0, start);
  const match = rawText.slice(start, end);
  const after = rawText.slice(end);

  return (
    <div className="whitespace-pre-wrap text-base leading-relaxed">
      {before}
      <mark ref={markRef} className="rounded bg-[--color-citation-accent]/20 px-0.5 text-inherit">
        {match}
      </mark>
      {after}
    </div>
  );
}

function TranscriptBody({ rawText }: { rawText: string; segments: TranscriptSegment[] }) {
  return <div className="whitespace-pre-wrap text-base leading-relaxed">{rawText}</div>;
}
```

Note: `TranscriptBody` currently ignores `segments` (it's accepted for a future per-timestamp-block rendering enhancement noted in the spec, but the minimal version that satisfies the test and the highlight requirement just renders `rawText` as one block — segments become load-bearing once timestamp-gutter rendering is added, which isn't required by any test here, so it isn't built speculatively per YAGNI).
